# 设备与同步诊断

## 已验证与未验证（2026-09-16）

验证分为四层，不能用前一层代替后一层：

1. 接口接收：HTTP / JSON 表示已接收请求。
2. Zepp 云端：当天汇总、原始分钟明细和设备归属能够读回。
3. 官方 App：当天首页、当天详情是否变化。
4. 第三方：微信、支付宝、QQ 是否显示对应步数。

受控实验发现旧模板的全天分钟记录合计为 125 步；只改汇总可得到高汇总，App 当天却不一定变化。保留原始分钟记录并在两个已过去的空白分钟分别追加 120 步后，云端明细由 125 变为 365，官方 App 当天也显示 365。再次对照的云端明细为 605，汇总仍为 8472；微信持续显示 283。第二次的 App 显示未核对，微信同步成功尚未得到证明。

云端创建虚拟 Mi Smart Band 5 NFC 后，App 能显示该设备，但状态为“未启用”。绑定记录不等于蓝牙启用。APK 静态分析显示活动设备选择与启用状态有关，但没有证据证明修改某个云端标记就能解决第三方同步。代码不会尝试伪装蓝牙启用。

历史周统计与当天展示可能使用不同的数据处理路径；历史统计有记录不能证明当天明细有效。尚未确认只在 22:00 同步的规则，晚上观察属于对照实验。公众号的排行榜入口若打开同一个微信排行榜，不算一份独立的华米读数。

## 用户操作

控制台“设备与同步诊断”提供：

- **读取设备与明细**：只用当前有效凭据 GET 设备列表和当天数据，展示设备状态、汇总、分钟合计和一致性。优先复用有效凭据，失效时尝试 app_tokens 续用；不通过客户端登录兜底。续用失败时在当前页面输入原账号密码恢复，密码不保存。
- **绑定一次并核对**：仅在完整设备列表为空时创建一条未启用的虚拟设备。明确勾选确认后才 POST。已有设备不解绑、不重复创建。不保证微信同步。
- **追加 240 步并核对**：唯一手环、本人当天唯一原始记录、设备 ID 匹配、3/8 字节格式明确时才允许。只改两个已过去的空白分钟；各 120 步；保留其余字节、来源、已有 summary 字段及有效 UUID。原有高汇总不会被调低，也不会被称为已修复。
- **诊断记录**：本站独立记录，显示提交前、预期及读回值。打开页面与刷新记录只读 D1，不访问 Zepp。

追加限每天一次（北京时间），任何目标高于 50,000 步、明细不足、设备歧义、合并数据不同、跨天、凭据失效、账号过期或账号有任务时拒绝。没有原始分钟记录时不凭空生成基线。已有自动上传逻辑没有改为这个实验算法。

实验期间不要在手机或其他工具同时写入；本站账号锁只能约束本站任务，无法锁住第三方。官方 App 登录可能使本站凭据失效。结果不确定时只读核对，不反复登录/提交。虚拟绑定不应宣传为已解决第三方同步。

## 实现和失败语义

- `/api/sync-lab` GET：当前账号最近 20 条记录、当日追加标记和绑定标记。
- `/api/sync-lab/inspect|bind|append` POST：继承同源、会话、CSRF、使用期与限流检查；修改需 `confirm: true`。
- `sync-lab.js`：当前凭据校验、严格账号归属、账号 300 秒互斥租约；提交前再次检查日期、会话、租约、使用期。追加前再读基线；发生变化即拒绝。
- `minute-plan.js`：纯函数。只识别 mode=126 且其余字节全零的空白分钟，最多两分钟，拒绝不支持的格式和不同的 mergedRawData。
- `sync_lab_claims`：上游 POST 之前持久化唯一提交标记，绑定每账号一次，追加每账号/北京日期一次。HTTP 超时、进程中断或结果写库失败都不会自动重复 POST。标记保留在删除资料之后，避免重新注册绕过；仅存内部账号编号、操作编号、日期/类型与时间，不含登录凭据或原始健康记录。
- `sync_lab_operations`：只保存脱敏设备尾号、数值和过程，不保存上游响应、原始健康字节、密码或令牌。删除本地账号时删除这些记录。
- 正常结束释放租约；中断后租约自然到期。`submitted`/`unconfirmed` 表示提交可能已发生，不能当作失败后重试的依据。只读核对产生新记录，不篡改先前提交结果。
- GET 最多重试一次，POST 从不重试；所有外部请求有超时与响应大小上限。

无法消除外部设备在最后一次 GET 与 POST 之间写入的竞态，也没有微信服务端推送回执。即使读回字节完全匹配，界面也只声明 Zepp 已读回，绝不标为微信同步成功。

## 部署与验证

先运行 `npm test`，再应用 D1 迁移 `0009_sync_lab.sql`，然后部署 Worker。迁移只新建诊断表，不修改账号、凭据、计划、现有任务或 Zepp 数据。

测试覆盖 3/8 字节保留、空白分钟识别、跨天/设备/来源校验、50000 上限，以及 workerd+D1 中的认证、CSRF、过期、租约、账号隔离、只读、重复提交、超时后拒绝重发与删除资料后保留标记。上游全部为隔离模拟响应；测试不会登录或修改真实账号。

协议参考：原始 [MiMotion](https://github.com/TonyJiangWJ/mimotion)、[netcccyun/toolbox](https://github.com/netcccyun/toolbox) 的 XiaomiSport 设备绑定实现（研究基准提交 `70c00a945d68`），以及本地官方 App 行为对照。使用的是非公开接口，不是 Zepp 官方开发者集成，接口格式可能变化。仓库不包含解包 App、账号凭据或原始个人数据。

## 原地恢复连接

`POST /api/renew` 仅尝试当前凭据复用/续用；`POST /api/reconnect` 仅在当前网页会话、CSRF 验证和显式勾选登录影响之后接受原账号密码。当次登录返回的 Zepp 用户 ID 必须与当前本站身份匹配，不能覆盖为其他账号。两条路径共享账号租约及每 10 分钟 3 次限流；成功后轮换网站会话和 CSRF，保留使用期、范围和计划开关，不排队任务。已暂停的计划需要用户手动恢复。密码不进入 D1、任务消息或浏览器存储，表单提交时清空密码框。打开页面不会自动登录。诊断读取时会续用现有凭据；真正失效则暂停计划、提示原地恢复。
